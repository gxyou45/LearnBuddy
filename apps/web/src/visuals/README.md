# 词语配图

使用完整 `word` 精确查找 `word-visuals.json`，不按单字、子串或课程主题猜测含义。例：“香蕉”和“香甜”分别匹配，“海豚”不会决定“大海”的图标。

素材类型：

- `emoji`：有明确对应物的系统图标；外观随设备字体变化。
- `sketch`：`sketches.ts` 中的原创 SVG 简笔画，120×100 坐标，轮廓与颜色辅助辨认，不使用远程图片。
- `color`、`count`、`symbol`：颜色、数量、符号使用实际示意，不用统一调色盘或数字键图标。
- 未匹配：显示中性“ 一起说一说 ”提示，保留完整词语与陪读流程。不以通用物品图假充释义，也不宣称已完成情境配图。

`ContentImage.CharacterIllustration` 优先保留课程包显式指定的专用图；其余使用这份词语表。新课程的 `han-` 字号不再回退到旧的宽泛类别图标。原十课没有命中新表的词仍使用原有素材（例如“来”的方向场景）。认字、读词、辨义共用组件；后台选项预览也使用相同词语表。

`curriculum-1000-v1` 中已知自动生成的共读词卡在客户端按同一词语表显示，相同词语去重。其他发布版本及人工配图仍走原素材路径。此次为展示修正，不重写不可变发布包、课次、题目 ID 或学习记录；旧媒体文件保留。未来发布新课程版本时，应将经审定的配图纳入内容包并复验，不要复用早期 `build.py` 的按单字分类配图规则。

新增词语时优先检查现有系统图标能否准确表达完整词义，找不到就绘制具体的 SVG 场景；不能只因为同属一个类别就复用。需要亲属关系、动作顺序、语境才能说明的词，保持陪读并安排情境图，不凭人物外观猜测亲属身份。PNG/JPEG 素材或复杂绘画应使用课程包图片机制，不放入字符串模板。

验证：`npx vitest run tests/word-visuals.test.ts`；`PLAYWRIGHT_BASE_URL=http://localhost:8080 npx playwright test tests/e2e/word-visuals.spec.ts --workers=1`。素材预览：`node --import tsx scripts/acceptance/visual-catalog.ts`，输出到 `验收/2026-09-23-图标优化/`（可用 `ACCEPTANCE_REPORT_DIR` 改目录）。

SVG 为项目内原创，系统 Emoji 使用设备自带字形；没有引用第三方图片站素材。机器检查仅保证引用与渲染，不替代教学审校。
