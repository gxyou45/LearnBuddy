# DEV-19 逐字录音校准

自动估算不等于人工审听。`reviewStatus: pending` 是素材整体审校状态，与 `cues.status: reviewed`（仅时间点已审听）独立。

## 第一课试点

在内容工作台 `/admin` 新建草稿，进入“素材与声音”，先选第一课的 `audio-word-wo`、`audio-word-ba`、`audio-word-ma`、`audio-family-reading`，随后核对单字录音。

1. 播放录音，暂停到每个字的开始和结束，填写或记录对应秒数，再用“从此字试听”复核。
2. 每个 Unicode 字符（含标点）对应一组起止时间。标点不发音时可用相同起止时间；结束不能超过下一字开始或录音总时长。字间空白不显示当前字高亮。
3. 完整审听后点“我已逐字审听，确认时间点”。这会绑定录音 SHA-256 与文字；任何时间点编辑都会重新变为待审听，改文字或换录音会清除旧时间点。
4. 保存草稿、校验并预览；逐项检查暂停、重播、切换步骤和录音失败。导出已审听时间点作为独立 JSON 备份。

目前仓库的人工校准表为空；自动化测试里的秒数仅为功能夹具，不能用于实际教材。

## 重新生成与导入

原型十课的已审听数据放在 `scripts/reading-cue-overrides.json`，按音频素材 ID（如 `audio-word-ba`）索引。`generate-reading-timings.py` 只写估算文件，绝不写人工表；`npm run content:export` 最后合并人工表，文本、录音哈希或时长不符会失败，不静默退回估算。

完整课程或其他版本使用各自从管理台导出的校准表；先生成候选课程，再应用到一个全新的候选清单：

```sh
node --import tsx scripts/import-content/apply-reviewed-cues.ts curriculum-release/manifest.json reviewed-full.json calibrated-manifest.json
```

该命令不会覆盖源清单或已有目标；遇到不存在的素材、文字／录音变化、非法时间点会中止。校准表应单独保留并在每次重新生成后重用。正式导入前必须分配新的 releaseId，再走既有媒体、发布和兼容校验；不要覆盖已发布版本。已有学习档案仍固定原版本。

单条格式：

```json
{
  "audio-word-ba": {
    "text": "爸爸",
    "starts": [0.03, 0.34],
    "ends": [0.25, 0.60],
    "status": "reviewed",
    "audioSha256": "填写该录音的64位SHA-256，不使用此示例直接发布"
  }
}
```

上述秒数仅解释格式，不代表已完成审听。
